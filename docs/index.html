SMOP

SMOP solves the basis-pursuit denoise problem by tracing the Pareto frontier of the Lasso path with a sieving-based secant level-set method — sparse, fast, and numerically robust.

min ‖x‖₁  s.t.  ‖Ax − b‖₂ ≤ δ

Qian Li, Defeng Sun, Yancheng Yuan, An Efficient Sieving-Based Secant Method for Sparse Optimization Problems with Least-Squares Constraints, SIAM Journal on Optimization 34(2):2038–2066 (2024), doi:10.1137/23M1594443

01

The problem and the method

Basis-pursuit denoise — solved with secant level-set, not plain bisection min  ‖x‖₁  s.t.  ‖Ax − b‖₂ ≤ δ,   x ∈ ℝⁿ

SMOP implements the sieving-based secant level-set method of Li, Sun & Yuan (2024): it walks the Lasso path x(μ) = argmin ½‖Ax−b‖² + μ‖x‖₁ and roots the constraint ψ(μ) = ‖Ax(μ)−b‖ = δ with a fast outer secant loop — no plain bisection — while adaptive sieving keeps every inner Lasso solve on a small active set.

1

Level-set loop

Root-finding on ψ(μ)−δ = 0: secant steps (default) with analytic Newton and guarded bisection fallback, validated every iteration.

2

Adaptive sieving

Each Lasso subproblem is warm-started on a small active set and augmented from the KKT residual, following the reference control_addpram budget.

3

Inner solvers

Three solvers with a strict preference order — smoothing Newton, then SSNAL, and ADMM only as a last resort.

Inner-solver dispatch

Which inner solver runs, and when
Subproblem shapePrimary solverRationale
m > nr (tall)smoothing Newtonnr×nr normal equations; 30 s budget, falls through on failure/timeout
nr ≥ m or large active set (incl. m ≥ 3000)SSNALdense LDLT (m ≤ 1500) / PCG (m > 1500); nested linsys pass-through
both fail / disabledADMMstrict last resort only — never preferred for large active sets

Why it is fast

Fast secant method

Superlinear outer root-finding on ψ(μ) = ‖Ax(μ)−b‖ = δ — 3–7 outer iterations instead of the 16–20 a plain bisection needs.

Adaptive sieving

Column subsets are expanded only as needed, keeping every Lasso subproblem on a tiny active set — the engine behind the speed-up on large sparse data.

Second-order inner solves

Smoothing Newton and SSNAL solve each subproblem to high accuracy; the heavy linear algebra lands on tiny reduced systems.

Header-only C++17 + Eigen

No build system required for the core: #include "smop/smop.hpp" and compile. OpenMP parallelization on large sparse operators.

Installation

First, get Eigen 3.4.x headers into smop/third_party/eigen-3.4.0/ (or use your system package — see platform notes):

cd smop/third_party
curl -L -o eigen.tar.gz https://gitlab.com/libeigen/eigen/-/archive/3.4.0/eigen-3.4.0.tar.gz
tar xzf eigen.tar.gz        # -> third_party/eigen-3.4.0/
# 1. toolchain
sudo apt-get update && sudo apt-get install -y g++ libeigen3-dev

# 2. C++ (CMake)
cmake -S . -B build && cmake --build build --config Release
./build/test_cpp                          # regression suite (T1-T5)

#    or directly:
g++ -std=c++17 -O3 -march=native -fopenmp -I include -I /usr/include/eigen3 \
    examples/example_cpp.cpp -o example_cpp && ./example_cpp

# 3. Python
pip install numpy pybind11
cd python && pip install .
python -c "import smop; print(smop.version())"

# 4. R
cd R && R CMD INSTALL --preclean .
Rscript -e 'library(smop); print(smop_version())'

# 5. MATLAB / Octave
cd matlab
mkoctfile --mex -I../include -I../third_party/eigen-3.4.0 smop_mex.cpp smop_lasso_mex.cpp
octave --no-gui test_smop_octave.m

Quick start

One solve per language. Full option lists and result schemas: docs/INTERFACES.md.

#include "smop/smop.hpp"

Eigen::MatrixXd A = ...;             // m x n
Eigen::VectorXd b = ...;             // m
double delta = ...;

smop::SmopResult r = smop::solve_bmop(A, b, delta);
// r.x : solution;  r.info.status == 0 -> converged

smop::LassoResult lr = smop::solve_lasso(A, b, lambda);
import numpy as np, smop

A = np.random.standard_normal((40, 150))
b = np.random.standard_normal(40)
delta = 0.5 * np.linalg.norm(b)

res = smop.solve_bmop(A, b, delta, verbose=1)
x = res["x"]
print(res["status"], res["msg"])
print(np.linalg.norm(A @ x - b), delta)      # constraint satisfaction
library(smop)

res <- solve_bmop(A, b, delta, options = list(verbose = 0))
cat(res$status, res$msg)

lr <- solve_lasso(A, b, 0.05)
res = smop(A, b, delta);
fprintf('%d %s\n', res.status, res.msg);
fprintf('%g %g\n', norm(A*res.x-b), delta);

Solve a Lasso directly

Every level-set subproblem is an unconstrained Lasso — min ½‖Ax − b‖² + λ‖x‖₁ — so SMOP exposes it directly. Same core, same interfaces, verified KKT residuals below 1e-6 on all four.

smop::LassoResult lr = smop::solve_lasso(A, b, 0.05);
// lr.x   : solution
// lr.eta : relative KKT residual (< 1e-6)
lr = smop.solve_lasso(A, b, 0.05)
print(lr["eta"])        # 3.4e-07 on the interface test
lr <- solve_lasso(A, b, 0.05)
print(lr$eta)           # 6.7e-07
lr = smop_lasso(A, b, 0.05);
disp(lr.eta)            % 6.6e-07
